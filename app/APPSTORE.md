# Pyramid для iPhone: от аккаунта до App Store

Приложение — родная оболочка вокруг веб-версии. Внутри тот же код, что на сайте,
плюс родной слой управления звуком (`ios/App/App/AudioSessionManager.swift`):
громкий динамик вместо разговорного, музыка и голос не глушат друг друга, звук при
заблокированном экране, автоматическое восстановление после телефонного звонка.

Всё, что ниже, делается на Маке. Я не могу собрать приложение за вас: сборка и
подпись возможны только в Xcode на вашей машине. Моя часть — проект готов целиком.

---

## Часть 1. Аккаунты (один раз)

1. **Apple Developer Program** — developer.apple.com/programs. Стоит 99 долларов
   в год. Нужен Apple ID с двухфакторной защитой. Можно записаться как частное
   лицо (быстро, обычно день-два) или как компания — тогда понадобится номер
   D-U-N-S, и это дольше. Для начала хватит частного лица; в магазине тогда будет
   видно ваше имя как разработчика.
2. Дождитесь письма о зачислении. Без него Xcode не даст подписать сборку
   для TestFlight.

## Часть 2. Мак (один раз)

1. Поставьте **Xcode** из Mac App Store. Бесплатно, весит много, ставится долго.
   После установки откройте его один раз и согласитесь доставить компоненты.
2. Поставьте **Node.js** с nodejs.org — кнопка LTS.
3. Скачайте репозиторий с GitHub на Мак (зелёная кнопка Code → Download ZIP)
   и распакуйте.

## Часть 3. Открыть проект

В Терминале (Программы → Утилиты → Терминал):

```
cd путь/к/pyramid/app
npm install
npm run ios
```

Последняя команда соберёт веб-часть, синхронизирует её с проектом и откроет
Xcode. CocoaPods ставить не нужно: проект на Swift Package Manager — Xcode сам
скачает зависимости при первом открытии, подождите, пока внизу закончится
«Resolving packages».

## Часть 4. Подпись и первый запуск на своём айфоне

1. Слева в Xcode нажмите на синий значок проекта **App**, затем вкладка
   **Signing & Capabilities**.
2. Поставьте галочку **Automatically manage signing** и выберите свою команду
   в **Team** — после зачисления в программу она появится в списке.
3. **Bundle Identifier** — `com.pyramid.rooms`. Если Xcode скажет, что такой
   занят, поменяйте на что-то своё, например `com.ваша-фамилия.pyramid`.
4. Подключите айфон кабелем, на айфоне разрешите доверие компьютеру. Сверху
   в Xcode выберите свой айфон вместо симулятора.
5. Нажмите ▶. При первом запуске айфон может попросить включить **Режим
   разработчика**: Настройки → Конфиденциальность и безопасность → Режим
   разработчика. Включите, перезагрузите, запустите ещё раз.

Если приложение открылось и показало главную страницу — всё работает.

## Часть 5. TestFlight — раздать своим, без магазина

1. В Xcode сверху выберите **Any iOS Device (arm64)** вместо вашего айфона.
2. Меню **Product → Archive**. Подождите сборку.
3. В открывшемся окне Organizer: **Distribute App → App Store Connect →
   Upload**. Соглашайтесь с предложенным по умолчанию.
4. На **appstoreconnect.apple.com** → My Apps → ваше приложение → вкладка
   **TestFlight**. Сборка появится через 5–15 минут после обработки.
5. **Internal Testing** → создайте группу, добавьте себя и Лену по Apple ID.
   Внутренним тестировщикам сборка доступна сразу, без проверки Apple.
6. На айфонах поставьте приложение **TestFlight** из App Store, примите
   приглашение из письма — Pyramid установится оттуда.

Так можно жить сколько угодно: каждая новая сборка — повтор шагов 1–3,
тестировщики получают обновление автоматически.

## Часть 6. App Store

### Что приготовить заранее

- **Политика конфиденциальности** — обязательна. Она уже есть на сайте:
  `https://ваш-адрес.onrender.com/privacy.html`. Эту ссылку и укажете.
- **Скриншоты** с айфона: App Store Connect покажет, какие размеры нужны.
  Снимите главную, комнату, чат, панель «i». Делайте их в TestFlight-сборке.
- **Описание** на русском и английском. Короткое: что это, для кого, что умеет.
- **Возрастной рейтинг** — 4+. **Категория** — Lifestyle или Health & Fitness.

### Перед отправкой: собрать веб-часть внутрь

Пока в `capacitor.config.json` есть блок `"server"` с адресом, приложение грузит
живой сайт — это удобно для тестов, обновления мгновенные. Перед отправкой в
магазин этот блок лучше убрать: Apple спокойнее относится к приложениям,
у которых интерфейс лежит внутри. Удалите блок `"server": { ... }` и снова
выполните `npm run ios`. Приложение будет открываться из своих файлов, а
к серверу ходить по адресу, вшитому скриптом `build-www.js`.

Если сервер переедет на другой адрес — поменяйте его в `build-www.js`
(строка с `PYRAMID_SERVER`) и пересоберите.

### Раздел «App Privacy» в App Store Connect

Честные ответы по нашему приложению:
- **Audio Data** — используется для функций приложения (голосовая связь),
  не собирается и не хранится.
- **Name** — имя, которое вводит человек, живёт только во время сессии и на его
  устройстве.
- Отслеживания нет, рекламы нет, аналитики нет.

### Заметки для проверяющего (поле Notes)

Это самое важное поле. Проверяющий один, а приложение рассчитано на двоих.
Напишите примерно так (по-английски):

> Pyramid lets two people in different places listen to the same music in
> perfect sync and talk to each other, inside a 3D marble room. It needs two
> devices to test: open the app as Master, press Invite and open the link on a
> second device (any browser works). Both will hear the same track at the same
> moment and can talk. The microphone permission is for the voice link only;
> nothing is recorded or stored. The native layer manages the iOS audio session
> so voice and music play together through the loudspeaker and keep playing with
> the screen locked. A ready room for testing: https://ваш-адрес.onrender.com/?room=review

### Возможный отказ и что отвечать

Apple иногда отклоняет приложения с формулировкой «это просто сайт»
(guideline 4.2, Minimum Functionality). Наш ответ по существу: приложение делает
то, что сайт на айфоне сделать не может — управляет звуковым режимом телефона,
выводит в громкий динамик, держит звук в фоне, не глушит музыку во время
разговора. Это и есть причина существования приложения, и так и напишите
в ответе на отказ. Если откажут повторно — напишите мне, подберём формулировки.

## Часть 7. Обновления

- **Пока блок `"server"` на месте**: обновили сайт на GitHub — обновилось и
  приложение, ничего пересобирать не надо.
- **После перехода на встроенную веб-часть**: любое изменение интерфейса —
  это новая сборка: поднять `MARKETING_VERSION` в Xcode, `npm run ios`,
  Archive, Upload, и Apple снова проверяет (обычно 1–3 дня).

## Что здесь лежит

- `capacitor.config.json` — имя, идентификатор, адрес живого сайта.
- `build-www.js` — собирает веб-часть внутрь и вшивает адрес сервера.
- `ios/App/App/AudioSessionManager.swift` — управление звуком телефона.
- `ios/App/App/AppDelegate.swift` — включает его при запуске и возвращении.
- `ios/App/App/Info.plist` — право на микрофон (с текстом для пользователя),
  звук в фоне, только портретная ориентация.
- `assets/icon.png`, `assets/splash.png` — значок и заставка; уже положены
  в проект в нужных размерах.
